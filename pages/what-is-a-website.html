Documents and programs

If you've used a computer before, you should be familiar with the concept of a document.

A file with the .doc or .docx extension is a Word document: opening one with the Microsoft Word program will allow the user to view said document. A file with the .odt extension is an Open document, and the primary program to open and view the contents of one is LibreOffice Writer. It is also possible to open Word documents with Writer and Open documents with Word, courtesy of the developers for our convenience.

Note for developers: yes, I know, the file extension has nothing to do with the file format. It doesn't matter in this explanation. If you are learning something from this explanation, your files' extensions will probabily match their formats. We'll get to the difference later.

This pattern repeats all over computers: an image (typically a file with the .jpg or .png extension) can be viewed with any image viewer. There should be one that comes with your operating system. A video (for example, a file with the .mp4 extension) can be viewed with a video player, and so on.

Here comes the browser: Google Chrome, Firefox, Microsoft Edge, Dia (God forbid), Ladybird and a dozen others that people made over the years. They are amongst the most complicated programs that exist, and they all have the same job: to allow you to view a special kind of document, the HTML document.

What follows is a short Q&A, for my and everyone else's mom.

Isn't Google Chrome internet?
No, Google Chrome is a program on your computer. More specifically, a browser.
Isn't a browser internet?
No, a browser is a kind of program on your computer.
Don't I need a browser to use the internet?
Almost definitely. A browser is still just a program.
Isn't a browser the same as a search engine?
No. I hope the difference will be clear in a bit.
Are you sure a browser only displays documents? Some websites play videos, and have buttons that I can click.
HTML documents are much more complicated than printed documents. All those features (videos, buttons, etc.) are still considered part of a document. That's why browsers are complicated programs.

For all your other burning questions, I hope you'll find the answer going forward.

Where do babies HTML documents come from?

Ok, I lied. Browsers are a little more special than other document viewers, because they allow you to view documents that are stored on your computer or that are stored on someone else's computer. That explains how you are able to view this document, on your PC or your smartphone, despite you not having downloaded it on the device.

Note for developers: yes, this is another simplification. HTML documents don't have to come from files.

So, you are currently viewing this document on your computer, but you don't have it stored. How's it possible? How does it work? Of course, you can't just read any file on anyone's computer, and thank goodness. That would be terrible. No, I have to setup my computer to make everything work.

First of all, both our computers need to have special hardware that allows them to talk to each other. Without it, any exchange would be impossible. Thankfully all modern computers come with that hardware, so it's not a concern.

Second, they need to be connected to a network. This is also almost always true for today's computers.

Third, they need to start exchanging messages. Your computer needs to ask mine: Can I get that HTML document?, and mine needs to say: Sure, here it is. (along with a copy of the entire document). Your computer now has a copy of the document, and it can display it.

To use the correct terminology, the computer that asks for the document is called a client. The computer that sends the document back is called a server. Just to be confusing, the program that is responsible for sending the document, that runs on the server computer, is also called a server.

When people say that they made a website, they don't usually mean that they also made the server program. What they usually do is use a third–party service, either paid or free with limitations. While it's not particularly difficult to make a basic server program, it's extremely difficult to make a secure one. One that resists against potential attackers that might try to hijack the conversation between the client computer and the server computer.

If you are not a programmer, using a third–party service is what I recommend.
